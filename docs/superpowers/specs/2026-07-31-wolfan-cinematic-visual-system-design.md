# 小狼个人网站电影感视觉系统设计

## 1. 设计目标

将当前“Hero 有明确 IP、其余页面接近通用作品集”的网站，改造成一段从黄昏经过夜晚、最终抵达清晨的青春旅途。

用户明确喜欢新海诚作品带来的视觉体验。实际设计不以复制某位在世创作者的独特笔触为制作方法，而是把用户真正喜欢的特征转化为可执行规则：通透天空、强烈时刻光、精细环境、列车与水面、安静的青春情绪，以及用光线推动时间变化。

成功标准：拿掉 Hero 单独看作品区、关于区或结尾，访客仍能判断这些页面属于“小狼 wolfan”的同一个世界。

## 2. 总体方向

采用“电影章节式为主、车窗旅途式为辅”的结构。

- 电影章节式负责页面节奏：每一屏像一个镜头，有明确的情绪、光线和主角。
- 车窗旅途式负责统一作品：玻璃反光、窗框比例、景深和经过感暗示“沿途看见的四个世界”。
- 不制作火车驾驶舱、路线图、横线圆点或过度拟物的列车 UI。
- 不继续扩大统一 Bento 卡片网格。
- AIGC 负责世界观；真实截图、录屏、仓库和数据负责可信度。

## 3. 白发少年出现规则

白发少年只在三个有叙事意义的位置出现。

### 第一次：Hero

- 完整人物。
- 继续使用现有黄昏与夜晚背景。
- 建立“小狼”的外貌、情绪和旅途起点。

### 第二次：关于小狼

- 轻量出现。
- 使用远处侧影、玻璃倒影或河边小比例人物，不使用大幅正面角色。
- 人物占画面高度约 18%—28%，承担“他仍在途中”的感受，不抢夺文字。

### 第三次：清晨结尾

- 再次完整出现。
- 使用背影或四分之三侧面，面向列车与晨光。
- 与 Hero 构图形成呼应，完成黄昏—夜晚—清晨的情绪闭环。

作品区和实习区不出现人物，避免角色沦为重复吉祥物。

## 4. 页面章节

### Chapter 01：黄昏 / 夜晚 Hero

保留最终文案：

```text
NEXT STOP · UNNAMED
李学钦 · 小狼 wolfan
流水不争先，争的是滔滔不绝
```

- 桌面文字保持右置，不覆盖左侧少年。
- 手机使用专门裁切，人物在左、文字在右下。
- 日夜切换改变背景、遮罩、导航和后续内容区的色彩状态。
- 背景只做极轻的镜头呼吸，不让人物持续漂浮。

### Chapter 02：沿途的四个世界

作品顺序保持：

1. 《一笔留白》
2. 小狼协议
3. Python 自动化清洗工作台
4. 小红书创作

作品不再像四张同质卡片，而是四个具有不同镜头语言的窗口。

#### 《一笔留白》

- 旗舰横向章节，占据最大画面。
- 使用真实 8—12 秒游玩录屏作为主要媒体。
- 视觉材质延续游戏的水墨、宣纸、朱砂红，但外围环境仍属于网站的天空与列车世界。
- 一个视口内说明：为什么做、核心交互、15 关与立即试玩。

#### 小狼协议

- 展示一次真实需求从模糊变清晰的过程，而不是只放长截图。
- 媒体使用 6—10 秒对话或步骤变化录屏。
- 保留“37 人已使用”和 GitHub 入口。
- 视觉像夜间车窗上逐渐清晰的文字，但必须保持可读性。

#### Python 自动化清洗工作台

- 使用真实脱敏界面或 10—15 秒操作录屏。
- 镜头顺序：导入 CSV → 规则清洗 → 风险样本进入人工复核 → 最终导出。
- 明确标注“脱敏案例说明”，不伪装成对外 SaaS 产品。
- 保留 23 项测试、200 条脱敏回归集、正确自动处理率 78% 和适用边界。

#### 小红书创作

- 不只展示主页数据，增加 3—5 张代表作品封面或一次内容拆解过程。
- 展示选题、视觉、发布、复盘四个真实动作。
- 账号数字使用最新截图依据。

### Chapter 03：关于小狼

- 从作品信息密度切换到安静场景。
- 画面左侧或中央保留大面积天空、水面或玻璃反射。
- 小比例白发少年出现在远处。
- 保留核心文字：

```text
我喜欢把模糊的想法变成
可以被看见、被使用、被继续迭代的东西
```

- 删除重复的小型英文眉题，使用镜头编号或场景字幕时全站不超过两处。

### Chapter 04：真实经历

- 采用冷静、偏夜间的视觉状态。
- 不做路线图、时间线圆点或车票拟物。
- 使用场景明暗、段落宽度和排版节奏区分网易与生数科技。
- 每段回答四件事：面对的问题、本人负责的判断、形成的方法、可验证结果。
- 详细职责仍由 PDF 简历承载。

### Chapter 05：清晨 / 联系

- 使用清晨图作为全宽结尾，不再使用纯黑联系区。
- 人物位于左侧或偏左，联系标题和入口位于右侧。
- 保留“下一站，也许从一次对话开始”。
- 手机、邮箱、GitHub、简历下载均保持直接可达。
- Footer 使用：`Art direction, copy & build by 李学钦 · made with AI`。

## 5. 色彩系统

不再以暖米白作为整站默认底色。色彩从三张场景图中取样，并按时间状态组织。

### 黄昏状态

- 天空雾白：内容大面积浅底，应为低彩冷白，而非奶油米白。
- 夕阳珊瑚：主要按钮、关键数字、交互高光。
- 水面青灰：辅助文字、边界和次级状态。
- 深墨蓝：正文和深色章节。

### 夜晚状态

- 夜空深蓝黑：页面主背景。
- 月光冷白：正文与高对比文字。
- 路灯暖金：少量情绪高光。
- 水面蓝青：焦点、链接和玻璃反射。

最终 CSS 使用 OKLCH 颜色变量，并以实际场景图取样结果确定数值。任何正文对比度不低于 WCAG AA。

## 6. 字体方向

- 正文与界面：选择清晰、现代但不过度科技化的中文无衬线字体。
- 大标题：使用较有力度的中文展示字重，不依赖极端负字距制造设计感。
- 引语与情绪文字：可使用一款克制的开源中文楷体或人文书写字体，仅用于少量句子。
- 英文等宽体只用于真实技术信息或场景字幕，不再作为每个章节的固定眉题。
- 所有展示标题字距不小于 `-0.04em`。

正式实现前需要用实际中文文案制作字体对照图，再确定字体文件。网站优先使用自托管 WOFF2 子集，避免第三方字体服务阻塞。

## 7. 动效设计

### 原生 CSS 负责

- 按钮、链接、焦点和媒体 Hover。
- 150—300ms 的局部状态变化。
- 日夜主题基础颜色过渡。
- 减弱动画模式的静态或交叉淡化替代。

### GSAP + ScrollTrigger 候选负责

只有以下连续镜头需要时才引入：

- Hero 光线掠过与时间变化。
- 作品窗口使用遮罩或玻璃反光进入。
- 关于区从信息密集转为安静场景的章节转场。
- 夜晚经历区向清晨联系区的最终过渡。

禁止给每个元素统一套用上移淡入。每个章节只保留一个主动作，动效不能妨碍快速浏览和项目链接操作。

### Remotion

- 用于导出作品演示视频或 45—60 秒个人创作蒙太奇。
- 不作为浏览器运行时依赖。
- 未来蒙太奇以清晨画面收尾。

## 8. 第一批 AIGC 素材规格

素材统一存放到：

```text
个人网站/资料收集/视觉素材/电影感重构/
```

原始母版不直接放进部署仓库。

### A. 人物资产

需要：

- 正面
- 左右侧面至少一个
- 背面
- 四分之三侧面
- 远处小比例侧影

统一要求：

- 白发、深色连帽卫衣、现有人物比例与气质。
- 人物完整，不裁切头顶、脚和衣摆。
- 透明背景 PNG。
- 单张人物高度至少 3000px。
- sRGB。
- 不包含文字、Logo、光斑和复杂背景。
- 发型轮廓、衣服结构、鞋子和身体比例在所有姿势中保持一致。

### B. 关于区场景

- 母版：3840×2160，16:9，sRGB PNG。
- 时间：蓝调时刻或黄昏结束前后。
- 环境：河流、列车、电线、玻璃或水面反光中的一种或两种，不全部堆入。
- 人物：单独透明图交付；另提供无人背景。
- 构图：左侧约 55% 保留低干扰负空间供中文文字使用；人物建议位于右下三分区。
- 不生成任何文字、标识、假 UI 或水印。

### C. 清晨结尾场景

- 优先使用并统一优化现有 `清晨.png`。
- 母版统一到 3840×2160，16:9，sRGB。
- 人物位于左侧或偏左，右侧至少保留 42% 的低干扰区域供联系信息使用。
- 保留列车、河流、晨光和云层关系。
- 提供无人背景与独立人物版本；如果无法拆分，至少提供干净背景版本和完整合成版本。
- 不生成文字、Logo 或水印。

### D. 可选光效层

- 水面反光
- 玻璃光斑
- 云层亮度遮罩
- 很轻的雨滴或窗户反射

要求：透明 PNG、黑底可混合素材或短无缝视频；每层只表达一种效果，不能与人物和文字绑定。

## 9. 背景画质与网页版本

三张原始母版统一为 3840×2160。夜晚图不能只通过普通插值放大，需要使用高质量超分或重绘恢复细节，再检查人物脸部、列车线条、云层与电线是否出现伪影。

网页导出规则：

- 桌面 WebP/AVIF：最长边 2560px，单张目标 300—700KB。
- 手机竖版 WebP/AVIF：建议 1440×1920 或按最终裁切确定，目标 200—500KB。
- PNG/JPG 原图只作回退或母版，不作为首选传输资源。
- 当前主题背景优先加载；另一个主题背景延迟加载。
- 每张图写明 `width`、`height`，避免布局偏移。

文件命名：

```text
scene-hero-dusk-master.png
scene-hero-night-master.png
scene-about-bluehour-master.png
scene-contact-morning-master.png
character-wolfan-front.png
character-wolfan-side.png
character-wolfan-back.png
character-wolfan-three-quarter.png
character-wolfan-distant.png
```

## 10. 真实项目媒体规格

### 录屏

- 分辨率：1920×1080。
- 帧率：30fps。
- 时长：6—15 秒。
- 无鼠标乱晃、通知弹窗、个人隐私和内部数据。
- 关键动作在前 2 秒内出现。
- 保留无声版本，网页默认静音播放。

### 图片

- 作品封面优先 16:10 或 16:9。
- 原始截图至少 1600px 宽。
- 不为统一比例拉伸图片，只裁切。
- 网站版本使用 WebP/AVIF 并懒加载。

## 11. 响应式与可访问性

- 不能简单把桌面背景居中裁成手机图；重要场景需要独立手机裁切。
- 文字不得压住人物脸部、手部和关键环境主体。
- 所有触控目标至少 44×44px。
- 动态媒体必须默认静音，不自动播放声音。
- 视频需要静态 Poster 和失败回退。
- 主题按钮的视觉文字与无障碍操作名称必须指向同一个状态模型。
- `prefers-reduced-motion` 下取消视差、遮罩和连续滚动编排。
- 内容默认可见，任何动画脚本失败都不能造成空白。

## 12. 实施阶段

### Phase 1：素材与字体验证

- 收集人物、关于区、清晨和真实项目媒体。
- 统一人物一致性与背景画质。
- 制作字体对照和场景色板。

### Phase 2：页面视觉重构

- 移除通用暖米白和过度卡片化。
- 重做作品、关于、经历和联系四个章节。
- 保留现有真实链接、简历和证据数据。

### Phase 3：动效

- 先用 CSS 完成静态和基础交互。
- 按已确认分镜决定是否引入 GSAP + ScrollTrigger。
- 加入真实作品录屏和失败回退。

### Phase 4：验收与发布

- 桌面、平板、手机分别检查日间与夜间。
- 测试键盘、减弱动画、慢速网络和媒体加载失败。
- 核对所有数字、链接、简历和公开边界。
- 提交、推送 `main` 并核对 GitHub Pages。

## 13. 验收标准

- Hero 以下仍具有明确的小狼 IP 与同一电影世界感。
- 白发少年只在 Hero、关于、清晨结尾三处出现。
- 四个项目的视觉呈现不同，但交互规则一致。
- 每个核心项目能回答“为什么做、本人做了什么、结果、在哪里验证”。
- 不再依赖暖米白、统一圆角玻璃卡和重复英文眉题制造设计感。
- 日夜主题不只是换 Hero 图，内容区色彩与氛围同步变化。
- 动画失败时内容仍完整可见。
- 首屏只优先加载当前主题背景，移动端使用适配裁切。
- 项目数据、实习经历与媒体均真实可公开。
- 网站仍保持静态部署，Remotion 不成为运行依赖。
